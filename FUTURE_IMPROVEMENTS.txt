A1-A18 [FIXED] (first pass: schema comma, role names, ports, requirements, ai_query_logs, random AI

A19 [FIXED] Candidate matching page showed "Unable to load candidate matches", 0 applicants and no
            required experience when some CVs were not processed yet: an unprocessed CV has no education
            level (NaN) and NaN is not valid JSON, so the whole answer failed, and the page built
            everything from that one answer. Now: NaN -> null in every AI answer; the job, its
            applications and the AI ranking load separately (an AI failure shows a message + Retry);
            the page says "X of Y CVs analysed" and analyses the remaining CVs with a progress bar.
            Tested on job #34: 0/15 -> 15/15 analysed, ranking with scores and AI reasoning.
A20 [FIXED] An HR manager opening an admin-only address was logged out (any 403 cleared the session).
            Only a 401 (expired / invalid session) logs out now.
A21 [FIXED] The leave page loaded the latest 200 requests only: pending requests older than that were
            invisible. It now loads every pending request plus the recent history.
A22 [FIXED] The high-risk KPI fell back to an SQL heuristic (685 people) when the AI engine was down,
            which contradicted the model (163). The Overview now shows "—" / "AI engine unavailable".

D1-D7, D11 [FIXED] (tenure, protected attributes, caching, sync endpoints, HTTP codes, stored chats,

            is presented as a reading aid (AI models page). Script: models/recruitment/evaluate_matcher.py.
